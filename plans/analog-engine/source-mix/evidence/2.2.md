# Step 2.2 evidence — public source-mixing documentation

- Status: **Verified**
- Scope: public synth factory and sub-layer documentation, reference-index integration, and executable example validation. Step 2.3 native timing/stereo/listening acceptance was completed subsequently.

## Documentation

Added focused reference pages:

- `docs/reference/instruments/synth.md` documents default, gain-only, basic,
  unison, selector-plus-gain, and explicit-`undefined` factory forms; selector
  precedence versus numeric shorthand; aliases; single-slot inputs; source
  routing; gain/lifetime semantics; and deferred scope.
- `docs/reference/instruments/sub.md` documents all three required-gain forms,
  defaults, replacement, canonical waveform aliases, fixed octaves, input
  representations, invalid raw-array/extra-argument forms, pitch/stereo/lifetime
  behavior, and layer envelopes.
- `docs/reference/instruments/index.md` links the synth factory and `.sub()`
  references while preserving the existing sampler/shared-method entries.

The pages explicitly distinguish `sourceGain`/`subGain` from shared
`.gain()`/`.adsr()`, describe additive pre-effects mixing and headroom without
automatic normalization, and state static negative flooring without mutating
reusable values while preserving signed automation semantics. They include
muted-main/sub-audible, stereo-unison/centered-sine-sub, layer-envelope, and
string/`d.sh()`/`d.str()` examples. The two `d.str()` geometries are documented
as successive bars versus within-bar values. Invalid snippets are labeled and
excluded from executable validation; signature, diagram, table, and prose
blocks are explanatory rather than executable.

At this documentation gate, the roadmap was still unchecked for the feature and
linked both the source-mix specification and implementation plan. It explicitly
left native and final acceptance pending at that stage; Step 2.3 subsequently
completed the Phase 2/full-feature gates.

## Example validation

The added Fluid test
`packages/fluid/src/__tests__/evaluate-source.test.ts` runs **35** unique
executable documentation examples through the existing public
`evaluateSource()` path. Each example constructs a fresh graph, calls `.push()`,
and asserts that exactly one instrument is produced; schema validation occurs
through the normal Fluid `getSchema()` path. The examples cover all documented
factory/sub forms, aliases, gain representations, direct automation sources,
replacement, main-zero/sub-audible mixing, unison chaining, layer envelopes,
and both structured bar geometries.

Two intentionally invalid raw-array/extra-argument snippets in `sub.md` were
not evaluated as successful examples. The text signatures, signal diagrams,
tables, and explanatory snippets were also intentionally excluded.
