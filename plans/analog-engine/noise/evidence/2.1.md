# Step 2.1 stateful noise DSP evidence

- Date: 2026-10-19
- Scope: worklet-local white/pink noise generation, deterministic timing, and statistical characterization. No adapter, engine registration, public API, or native browser integration is included.

## Implementation

- `packages/worklets/src/processors/noise-processor.ts` uses a nonzero-state xorshift32 PRNG. Seeds are internal numeric options; invalid or zero seeds resolve to a deterministic fallback. The sample loop allocates nothing and carries PRNG/filter state across process blocks.
- White output is uniform `[-1, 1)`, with no per-note normalization. Pink output uses the stateful seven-coefficient Paul Kellett-style filter and a fixed `0.33` output calibration selected to keep pink and white RMS levels approximately matched.
- Start and stop frames gate exact sample boundaries. Constructor frame options support offline scheduling; `start`/`stop` control messages support cancellation and late timing updates. Completion posts `{ type: "ended" }` once and returns `false`; malformed options/messages are ignored without throwing.
- Pink coefficient provenance: Paul Kellett, “Pink noise filter,” music-dsp.org, including the linked `pink.txt`: <https://www.musicdsp.org/en/latest/Filters/76-pink-noise-filter.html>. The implementation independently transcribes the published equations rather than copying source code; no third-party package or source file was added. The page identifies the author/source but does not publish a separate software license.

## Measurements and tests

- The focused suite uses 10-second runs, discards the first 2 seconds, and applies Hann-windowed Goertzel estimates averaged across five nearby frequencies at each octave from 125 Hz through 8 kHz. It checks 44.1, 48, and 96 kHz.
- Representative 48 kHz, seed `0x12345678` results after settling: white mean approximately `-0.0018`, RMS `0.5777`, PSD slope `+0.05 dB/octave`; pink mean approximately `-0.0412`, RMS `0.5744`, PSD slope `-2.95 dB/octave`.
- Focused noise suite: 10 tests passed.
- Full worklets suite: 5 files, 51 tests passed.
- Worklets TypeScript check, ESLint, Prettier, and `git diff --check` passed.

These are automated DSP/lifecycle checks, not native audio or human listening approval. Native adapter timing and processor-error coverage remain Step 2.2.
