# Step 3.1 acceptance evidence

Phase 3 is complete. The saw-only unison feature was documented, manually
reviewed, individually approved, and integrated without changing existing
references.

## Documentation

- Added the saw-only unison API section to `packages/fluid/README.md`, covering
  basic versus unison selectors, `unison`/`uni`, saw-only shape selection,
  engine/waveform schema identity, voices versus musical polyphony, cents
  spread versus stereo width, continuous LFO/MIDI control, runtime bounds,
  deterministic phase intent, count compensation, and loudness limitations.
- Updated `plans/analog-engine/roadmap.md` to distinguish the delivered
  saw-only unison path from a future public supersaw engine. No public
  `supersaw` compatibility selector is documented.

## Candidate and approval

- The diagnostic case uses four active events per bar and high-note passages
  (`60, 72, 84, 96`). Focused schema inspection confirms all voice, spread,
  width, and note passages resolve as intended.
- Native regression coverage proves spread and width LFOs change the rendered
  output over time instead of behaving like one-time values by comparing an
  animated render with an otherwise identical frozen-control render.
- The diagnostic case was rendered twice before acceptance at 48 kHz stereo,
  Chromium `147.0.7727.15`, 137 BPM. Both runs produced identical metrics:
  196,976 frames; channel peaks `0.224591` / `0.227938`; RMS
  `0.0426332` / `0.0430720`.
- The user reported feeling good about manual testing and approved the exact
  unison candidate. No compensation, panning, phase, or performance concern
  was reported. No cross-device performance guarantee is claimed.
