# Step 2.1a implementation evidence

Revised the uncommitted original supersaw authoring slice to the agreed saw-only unison direction while retaining the verified Phase 1 processor/source internals.

- Public selectors are now `d.synth("unison")` and `d.synth("uni")`; both return the unison builder. No public supersaw selector or compatibility alias remains.
- Unison defaults to canonical `waveform: "sawtooth"` and exposes `.type("saw" | "sawtooth")`. Unsupported unison shapes fail at runtime and are excluded from the type surface; basic waveform selection remains unchanged.
- The schema now separates `engine: "unison"` from `waveform: "sawtooth"`. Basic schemas remain valid without an engine field. Validation rejects unsupported engine/shape combinations, known unison fields on basic synths, and the old `waveform: "supersaw"` shape.
- Runtime dispatch and source-parameter/LFO discovery now select unison by engine identity. Count/spread/width, shared ADSR/effects, MIDI/duck behavior, deterministic phase identity, and constructor-time frame scheduling remain on the existing shared path.
- Renamed the focused Fluid authoring test and builder to unison; internal `SupersawSource`/processor names and historical evidence remain unchanged as permitted by the revised specification.
